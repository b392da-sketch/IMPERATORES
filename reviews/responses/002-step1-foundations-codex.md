# Codex review 002 — M0 step 1 foundations

All 16 foundation tests passed on CPython 3.10.22 with NumPy 2.2.6 and CPython 3.12.14 with NumPy 2.5.5. The documented seed-1 march produced byte-identical JSON across two processes with different `PYTHONHASHSEED` values and across those two runtimes on this machine. It ran 1,800 ticks and recorded four arrivals and 361 snapshots. The reviewed checkout was `0fb9e4d`. I compared it with remote `main` at `1ca3b6f` and confirmed that the scoped implementation, fixtures and tests match.

The phase order and entity iteration are explicit. I found no wall-clock input to the simulation or unordered collection driving its behavior. The CLI uses elapsed time in its console summary. The test march supplies initial orders in scenario data, and the movement system computes arrivals from state. The implementation has no commander decision code yet.

## Findings

Reproductions use the repository root. In Python snippets, `p = "scenarios/test_march.json"` and `w = scenario.load(p, 1)` unless stated otherwise.

1. **High — Removing or inserting an entity rekeys surviving entities.** `imperatores/scenario.py:47–51`, `imperatores/state.py:107–108`, `imperatores/systems/movement.py:61`. Entity IDs double as list offsets, parent references and RNG keys. A paired reserve-removal run can therefore change unrelated draws and silently retarget a relationship to another entity. This undermines the controls for M0 §7.1. **Reproduce:** In a copy of the march, give the last entity `{"kind":"move_to","x":3000,"y":1500}`. Run for 40 seconds with seed 1, then delete the turma at index 3 and repeat. The last entity changes from ID 4 to ID 3, with final x changing from approximately 3459.5497 to 3460.1044. The removed unit had no interaction with it. **Fix:** Load explicit stable IDs, validate uniqueness and links, and separate ID lookup from iteration order. Key later orders, scheduled decisions and messages on stable identities that survive paired interventions. Add a reserve-removal test that asserts surviving IDs, relationships and random draws.

2. **Medium — Distinct RNG keys can produce identical streams.** `imperatores/rng.py:20–28`. NumPy expands large integers into multiple 32-bit words. The variable-length tuple passes through without an encoding that preserves component boundaries. Coercion through `int()` can also cause different invalid inputs to share the same cached generator. **Reproduce:** Compare `Random(5).gen("movement", 2**32+1).integers(0, 2**32, 4)` with the same call using key components `1, 1`. Both produce `[1137990624, 1499785002, 764940180, 3047742872]` on the reviewed runtime. On one `Random` instance, `gen("movement", 1.9) is gen("movement", 1)` is true. **Fix:** Require integer keys and define an unambiguous, versioned encoding, such as validated unsigned 32-bit components with a fixed schema per purpose. Keep stream identifiers unique and stable. Ordinary distinct entity IDs keep separate consumption counters. Once entities interact, a shared causal change can still alter when a given unit consumes draws, so use stable occurrence keys where a paired comparison requires alignment.

3. **Medium — Legal pace overrides can abort normal movement at the speed guard.** `imperatores/params.py:37–48,59–73`, `imperatores/systems/movement.py:61–66`, `imperatores/systems/observe.py:21–29`. The normal sample has an unbounded upper tail and movement has only a lower speed clamp. **Reproduce:** Call `engine.step(scenario.load(p, 2, {"pace_cavalry": 5, "pace_jitter": 0.2, "max_speed_any": 5}))`. All values resolve, then the turma moves 11.4 m against a 10 m limit and the first tick raises `ConsistencyError`. **Fix:** Bound or cap the model's actual pace at the physical limit, document how the cap interacts with sensitivity settings, and keep the independent observer guard. Test the upper-range combination and confirm forced displacement still fails.

4. **Medium — End-of-tick checks can miss invalid states and attach the wrong baseline.** `imperatores/engine.py:12–20`, `imperatores/systems/observe.py:15–34`, `imperatores/state.py:57–58`. On ordinary unchanged rosters the observer checks center position, net displacement, nonnegative counts and the three inclusive ranges, including rejecting NaN for those ranges. It compares by list position via `zip`, validates after all phases, and accepts fractional headcount bins. **Reproduce:** Subtract 0.5 from `e.fit` and add 0.5 to `e.dead` on `e = w.entities[0]`. Give it a hold task and set `e.order = 2`. `engine.step(w)` succeeds with fractional counts and order clamped to 1. Replace `engine.PHASES` in a throwaway process with two callbacks that increment and decrement `e.dead` respectively. The transient violation passes. Separately, call `observe.begin_tick(w)`, append `dataclasses.replace(e, id=10, x=-1)`, and call `observe.end_tick(w)`. The extra entity is skipped. **Fix:** Validate initial inputs and every entity's invariants, track positions by stable ID, and make roster changes explicit. Enforce integral counts and conservation at each headcount transition or phase boundary that can change counts. Endpoint speed checks measure net displacement and will need explicit movement accounting if several phases can move an entity per tick.

5. **Medium — A matching digest can hide different final states.** `imperatores/engine.py:18–25`, `imperatores/record.py:22–45`, `tests/test_foundations.py:27–35`. The digest covers events, scheduled snapshots, scenario bytes via their hash, seed and resolved parameters. The run duration, final tick, unsampled end state and full-precision trajectory are outside that comparison. **Reproduce:** Load two fresh worlds with the same file and seed. Run one for 2 seconds and the other for 4. The first entity reaches x ≈ 1001.9946 and 1004.0124 respectively, but both records share digest prefix `d51ff00b586218800`. **Fix:** Record actual run length and final state even between periodic snapshots. Define the viewer snapshot precision separately from exact replay verification. Compare full exported artifacts and per-tick state traces in the replay test. The different-seed test should compare state changes with jitter enabled because seed metadata alone changes the digest. Duration is also an input and should be included in the run identity.

6. **Medium — A live mutable object can rewrite an event after it was logged.** `imperatores/record.py:15–19,37–45`. This makes it easy for later belief updates or order stages to erase what was known when a decision happened. **Reproduce:** Call `record.log(w, "probe", 0, {"belief": belief}, causes)` with `belief = {"x": 10}` and a nonempty causes list. Save the digest, mutate `belief["x"] = 20`, and append to `causes`. The historical event and digest both change. **Fix:** Capture owned JSON data at log time, including nested inputs and causal references. Give later decision and order records typed IDs and immutable input snapshots. Test mutation after logging and keep decision scoring isolated from the true world.

7. **Low — Some provisional settings lack the promised validation or provenance.** `imperatores/params.py:19–26,32,50–73`, `imperatores/engine.py:19`, `imperatores/systems/movement.py:58`, `imperatores/scenario.py:15`. All listed parameters have inclusive ranges, allowed labels and a basis. The bounds check rejects out-of-range finite numerics and NaN. The five evidenced entries cite Polybius but lack the explicit evidence grade requested in M0 §8. The 30-degree movement threshold and default 20 m terrain cell size live outside the parameter registry. **Reproduce:** Resolve `{"snapshot_every_ticks": 1.9}`. The record advertises 1.9 ticks while the engine runs a one-tick cadence. Inspect the evidenced entries and the two literals at the cited lines. **Fix:** Declare integer settings as such and reject fractional or Boolean values. Add evidence grades and put tunable model constants in the registry or give scenario-specific values an explicit basis.

8. **Low — A rejected move still charges movement fatigue and disorder.** `imperatores/systems/movement.py:66–73`. **Reproduce:** Set the first entity's x to 4000 and its task to `{"kind":"move_to","x":4100,"y":e.y}`. One tick leaves x at 4000 but raises fatigue from 0 to about 0.0001333. With a rough starting cell the same logic charges order loss using the attempted distance. **Fix:** Validate movement targets and base movement costs on actual travel. Give a blocked attempt a separate cost only if the model specifies one.

## What the tests establish

The bad-side, unknown-stream and bad-override tests exercise their stated rejection paths. The parent fixture test verifies loaded integers and the size of one succession list. The rough-ground and pace tests show the expected directional effect in one configuration. The arrival test checks for a turma event and for nonempty cause fields. It could also check endpoint distance, transition to hold and a cause that identifies the initiating order when that exists.

The keyed RNG test shows independence from extra consumption by another ordinary key. The intervention test holds one unit in place and compares the final positions of three others. It does not compare their random draws, paths, event timing or the fifth entity, and it leaves all IDs fixed. The current conservation and teleport tests each inject one clear violation. Boundary, negative or fractional count, range, roster-change and intermediate-phase faults need targeted coverage. The JSON test checks Python's permissive serializer. Use strict encoding and schema assertions before relying on it as a viewer compatibility check.
